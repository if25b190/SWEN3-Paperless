# Database migrations

Production migrations are under `postgresql/` and use the PostgreSQL-specific
Flyway location configured in the application. The sole migration,
`V1__create_uuid_schema.sql`, creates the current UUID schema for a fresh,
empty PostgreSQL database. UUID IDs are generated by Hibernate, not by database
defaults. Hibernate schema validation remains enabled at application startup.

## Greenfield-only migration

This migration is a fresh-schema bootstrap, not an upgrade path. Do not apply it
to an existing database, baseline an existing schema, or treat an old Flyway
history as compatible with this version. Existing installations must be reset
and restored from a verified backup, or handled through a separate, explicitly
reviewed upgrade migration; no in-place upgrade migration is provided here.
Back up and verify any data that must be retained before resetting a database.

## H2 tests

Tests retain their existing H2 Hibernate `ddl-auto: create-drop` schema
lifecycle. Flyway is disabled for the test profile, so PostgreSQL migrations
are not run against H2.
